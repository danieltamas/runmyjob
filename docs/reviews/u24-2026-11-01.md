# U24 review, 2026-11-01 (Codex, read-only)

- P1 a FIFO in place of `guard.log` could hold the agent in the blocking open: fixed. Opens are O_NONBLOCK and only a regular file of this user is written.
- P2 trim races with concurrent appenders: fixed with a `guard.log.lock` flock around append and trim (best effort, 200 ms, then the append goes ahead unlocked: the verdict is never delayed longer).
- P2 permissive mode on an existing log: fixed, `fchmod 0600` on a file we own; a file of another user is not written.
- P2 `recent` trusted the file: fixed. It opens without following links, reads only the last 256 KB, accepts only `block` and `advise` lines and cleans every field again.
- P2 main-actor reads: fixed, the pane reads in a detached task.
- P2 per-append read above 36 KB: accepted: the log is bounded (1000 to 1200 lines, fields capped in scalars), so the read is a few hundred KB at worst.
- P2 field limit by Characters: not an issue, `UntrustedText.clean` caps in unicode scalars.

Not fixed: a symlinked `logs` directory is followed (the RMJ home is mode 0700 and owned by the user; an attacker who can replace it already owns the home).

Failing open: the guard stays ON when `config.json` is unreadable (the switch off must be a deliberate, readable `false`). `RMJ_GUARD=off` is exact; anything else leaves it on.
