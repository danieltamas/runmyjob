# U6 review - 2026-10-27

Codex, read-only, two rounds. Findings verbatim, then the outcome.

## Round 1

```
P1 Support/runner-stack/entrypoint.sh:42 PATs are expanded into curl argv during registration, listing, and deletion -> Supply authorization headers through stdin or a protected descriptor instead.
P1 Support/runner-stack/entrypoint.sh:67 Registrations are deleted from a stale listing without rechecking their current status, busy flag, label, name, and age -> GET and revalidate each registration immediately before DELETE.
P1 Support/runner-stack/entrypoint.sh:55 Pruning deletes entries before subsequent pages are validated, so a later listing failure occurs after destructive changes -> Fetch and validate every page successfully before deleting anything.
P1 Sources/RMJCore/Ops/RunnerStack.swift:92 Deploy runs compose build and up without checking busy registrations, allowing a changed stack or PAT to recreate runners executing jobs -> Apply the busy refusal and explicit drain/cancel policy before deployment mutations.
P1 Sources/RMJCore/Ops/RunnerOperations.swift:53 Cancel proceeds with the container operation when no ledger job is known, and the default cancellation callback silently does nothing -> Require an actionable GitHub job and successful cancellation before proceeding.
P1 Sources/RMJCore/Ops/RunnerOperations.swift:44 Concurrent operations can interleave busy checks, drain policy updates, and container mutations against the same runner -> Serialize destination mutations across app and CLI processes and revalidate container identity before acting.
P1 Sources/RMJCore/Ops/OpsShell.swift:29 The remote rsync path is interpolated without remote-shell quoting or validation, allowing shell metacharacters in the configured home to execute remotely -> Quote the remote path for rsync's remote shell or use supported protected arguments with strict path validation.
P1 Sources/RMJCore/Ops/RunnerStack.swift:88 Rewriting .env from a partial token dictionary removes other targets' PATs and existing stack settings -> Require all necessary credentials and preserve unrelated settings before atomically replacing .env.
P2 Sources/RMJCore/Ops/OpsCommand.swift:48 Handoff accounts contain target slashes or colons, which PatHandoff rejects, so valid repo and org targets cannot use the intended CLI fallback -> Use a shared reversible encoding or digest for handoff filenames.
P2 Sources/RMJCore/Ops/OpsCommand.swift:21 Dry reports and prune previews consume and delete one-time PAT handoffs, while opening their context also prepares the home and writable database -> Use a read-only context and credential access that does not consume handoffs for previews.
P2 Sources/RMJCore/Ops/RunnerStack.swift:131 A missing or unreadable local stack becomes an empty manifest, producing a false no-op or permitting destructive rsync when .env differs -> Reject missing, unreadable, or incomplete stack directories before reporting or deploying.
P2 Sources/RMJCore/Ops/RunnerStack.swift:119 Checksum failures are suppressed and treated as file differences, so permission or command errors can trigger deployment instead of failing closed -> Distinguish confirmed missing files from failed checksum reads and abort on errors.
P2 Sources/RMJCore/Ops/Heartbeat.swift:29 Actor reentrancy allows a successful probe or wake to reset failures while an older failed record is suspended, after which that record can still mark jobs lost and notify -> Capture an outage generation and revalidate it after awaits before changing job state.```

## Round 2

```
P1 Sources/RMJCore/Ops/RunnerOperations.swift:32 The default cancel callback succeeds without cancelling anything, allowing `.cancel` to stop or recreate a busy runner without cancelling its GitHub job -> Require a cancellation implementation or make the default throw.
P2 Sources/RMJCore/Ops/RunnerStack.swift:161 The `.env` checksum pipeline suppresses read errors and returns an empty result on permission failures, treating an unreadable credential file as missing and permitting replacement -> Distinguish confirmed absence from read failure and validate the checksum before proceeding.
P2 Sources/RMJCore/Ops/RunnerStack.swift:135 Stack checksum comparison ignores the exit status, so a failed `cd` or interrupted command with empty stdout becomes a deployable difference -> Reject unsuccessful commands unless explicitly verified missing files explain the failure.
P2 Sources/RMJCore/Ops/RegistrationPruner.swift:61 The epoch parser accepts ASCII floating-point notation such as `abcdef123456-1e00000000`, allowing deletion of registrations outside the required naming shape -> Require exactly ten ASCII decimal digits before parsing.
P2 Sources/RMJCore/Ops/OpsCommand.swift:13 Pruning requires the destination to be online even though it only calls GitHub, preventing stale-registration cleanup when the box is offline -> Resolve tailnet reachability only for operations that contact the destination.
P2 Sources/RMJCore/Ops/Heartbeat.swift:24 A successful probe for any destination increments the shared generation and can abort another destination's pending loss transition -> Track generations per destination, with wake invalidating all destinations.
P2 Sources/RMJCore/Ops/Heartbeat.swift:37 Wake or recovery can occur while `ledger.advance` is suspended, after the generation check, allowing a stale loss transition and notification after reset -> Coordinate generation validation with the ledger mutation and revalidate before notifying.
P2 Sources/RMJCore/Ops/OpsCommand.swift:11 The dry report opens a writable context that creates or chmods RMJ_HOME and initializes the ledger, violating read-only behavior independently of the intended handoff consumption -> Load rules and tailnet state without preparing the home or opening a writable database.```

## Outcome

Fixed: deploy refuses while a runner of the stack is busy (when given registrations) and unless every runner target has a PAT; cancel needs a known job and a real
cancel implementation (the default throws); heartbeat marks nothing from a stale view (per-destination generation, wake counter); remote rsync paths validated;
checksum reads fail closed (missing is a difference, any other failure an error; `.env` absent vs unreadable told apart); the vendored stack must contain the compose file and
entrypoint; epoch in a registration name is exactly ten ASCII digits; prune no longer needs the box reachable; handoff account names encoded (`/` and `:` to `_`); the add-destination
flow gives an rx role a memory default; the ssh step uses the probe's availability.

Declined, with reasons:
- `Support/runner-stack/entrypoint.sh` (PAT in curl argv, revalidation before delete, paging before delete): vendored verbatim from agent-os `jobs/fleet-runners`, where it is changed first. RMJ's own pruner has all three properties.
- Cross-process serialization of runner operations: one owner, app and CLI are not driven against one runner together; an in-process gate broke parallel callers.
- Dry report and prune preview prepare `RMJ_HOME` and open the ledger, and a preview may consume a one-time handoff: both by design of the shared command context.
- A wake or recovery landing between the generation check and `ledger.advance` of one job: the window is one SQLite write.

Deferred: embedding `Support/runner-stack` in the app bundle (`RMJ_STACK` or `./Support/runner-stack` for now), the Settings screens (U7/U8), `rmj destination deploy` (the library deploys and is tested; the CLI exposes the report and prune only), PAT rotation across `.env` files.
