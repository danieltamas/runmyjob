# Registry change review (Codex, read-only, 2026-10-28)

P2 Sources/RMJCore/Registry/RegistryStore.swift:105 - URLSession follows redirects automatically, allowing requests outside raw.githubusercontent.com/danieltamas/registry - Reject redirects or validate every redirect destination against the exact registry origin and path.
P2 Sources/RMJ/MoreAppsModel.swift:118 - Sequential icon downloads each receive a fresh 30-second timeout, so one refresh can exceed the contract's 30-second overall limit by minutes - Apply one deadline across the list and icon downloads.
P2 Sources/RMJ/MoreAppsModel.swift:59 - Any valid stored list wins over the bundle, including an older cache retained across an app update; offline users can therefore see releases older than the shipped snapshot - Record the snapshot read time and select the newest validated copy.
P2 Sources/RMJ/MoreAppsModel.swift:14 - A present, non-string sourceKey value becomes nil, allowing the placeholder CFBundleShortVersionString to compare as a release - Track source-key presence separately and show "Built from source" whenever its value is not a clean tag.
P2 Sources/RMJ/MoreAppsModel.swift:82 - Cached and bundled icons reach NSImage without RegistryIcon validation; an oversized or wrong-dimension cached PNG displays and permanently suppresses refetching - Validate bytes from every icon source before use and treat invalid cached bytes as missing.
P2 Sources/RMJ/MoreAppsModel.swift:119 - When an app changes icon paths and the new download fails, its previous cached icon is abandoned because display lookup uses only the new path - Retain the previous accepted icon per app as the failure fallback.
P2 Sources/RMJCore/Registry/RegistryStore.swift:49 - Files are written before their permissions become 0600, leaving a permissions window and potentially a non-private file if chmod fails - Create private temporary files with mode 0600 before writing, then atomically rename them.
P2 Sources/RMJCore/Registry/RegistryStore.swift:40 - Lexical path validation does not prevent an existing registry/icons symlink from directing network icon writes outside the store - Reject symlink directory components and perform writes relative to verified directory descriptors.
## Answers
- redirects: fixed, a redirect is refused. Deadline: the icons share one 30 s deadline that starts after the list is read. Newest copy: a stored read older than the bundled snapshot loses to it. sourceKey: a present non-text value counts as a source build. Icon bytes: cached and bundled icons pass `RegistryIcon.accepts` too. Modes and symlinks: files are created 0600 and renamed into place; a symlinked store folder is refused.
- previous icon kept when a changed icon path fails to download: accepted, not built (the card shows the bundled icon, else the glyph; the registry says a changed icon gets a new name).
