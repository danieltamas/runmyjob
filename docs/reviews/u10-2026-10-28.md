# U10 review (Codex, read-only), 2026-10-28

## Findings

P0 Sources/RMJCore/Agent/AgentTools.swift:190 - `route(path:)` calls `RepoIdentity.detect`, whose `git status` can execute a checkout's configured `core.fsmonitor` command, permitting arbitrary writes or ssh from a read-only tool - Disable executable Git helpers and optional index writes for agent inspection, or avoid invoking Git.
P0 Sources/RMJCore/Agent/AgentAccess.swift:11 - Foundation bridges JSON numeric `1` to `Bool`, so `{"agent_access":1}` enables access despite the requirement for explicit `true` - Require an NSNumber with CFBoolean type identity before accepting true.
P1 Sources/RMJCore/Agent/MCPServer.swift:133 - MCP startup opens the creating, migrating Database initializer, which takes a write transaction and can create schema even with agent access off; AgentCLI does the same - Open existing state through a read-only database connection without migrations or home preparation writes.
P1 Sources/RMJCore/Agent/MCPServer.swift:38 - Request validation ignores `jsonrpc`, accepts object/array/boolean IDs, silently drops explicit null IDs, and treats invalid params types as empty objects - Validate the JSON-RPC envelope and distinguish absent IDs from explicit null IDs before dispatch.
P1 Sources/RMJCore/Agent/MCPServer.swift:96 - The cap assumes `build(0)` fits, but an arbitrarily large string request ID alone can exceed 1 MB; error and non-tool responses bypass the cap entirely - Bound accepted request IDs and enforce the byte limit on every serialized response.
P1 Sources/RMJCore/Agent/MCPServer.swift:76 - An oversized fixed result becomes an error without `truncated: true`, violating the specified truncation contract for large `job` or `route` results - Return a schema-valid bounded result marked truncated.
P1 Sources/RMJCore/Agent/AgentJob.swift:20 - Splitting the stored display command on spaces corrupts quoted arguments and empty arguments, while always reporting `shell: false` misrepresents shell runs - Persist and return the original argv and shell flag.
P1 Sources/RMJCore/Agent/AgentTools.swift:199 - `inputs.tailnet` returns `Router.describe` without sanitization; unknown Tailscale backend text or errors can carry escapes and invisible Unicode into results - Sanitize this field before serialization.
P1 Sources/RMJCore/Agent/AgentTools.swift:151 - `destinations`, `tailnet`, and `route` await live Tailscale reads with a 10-second timeout, exceeding the specified 500 ms call budget - Serve a bounded local snapshot and mark unavailable or stale data explicitly.
P2 Sources/RMJCore/Agent/AgentLog.swift:44 - Resolving symlinks and subsequently opening the path leaves a replacement race; the opened file is not bound to the archive containment check, and non-regular files can block reads - Open relative to a trusted archive directory descriptor without following symlinks and verify the opened descriptor is a regular file.
P2 Sources/RMJCore/Agent/AgentTools.swift:32 - Each jobs page loads the entire ledger and log archive before applying pagination, making request cost grow with total history rather than page size - Push filters and cursor predicates into SQL with `LIMIT limit + 1`, then fetch archive metadata only for returned jobs.
P2 Sources/RMJCore/Agent/AgentLog.swift:27 - When the 8 MB window starts inside a line, the first fragment is discarded without marking truncation; a single longer line can produce an empty, supposedly untruncated log - Record window truncation and preserve a bounded marked fragment.
P2 Sources/RMJCore/Agent/AgentArguments.swift:53 - `since` accepts `+1h` because Int accepts a leading plus and the remaining validation only checks ASCII, contrary to the advertised digits-only pattern - Require every count character to be an ASCII digit before parsing.

## Disposition

Fixed: both P0 (the route tool no longer runs git, so a checkout's fsmonitor cannot execute; `agent_access` must be the JSON literal true), the JSON-RPC envelope and id checks, the `job` result truncating its events instead of failing, quote-aware argv, the sanitised tailnet line, `since` digits only, the log window marking a cut head.
Not changed: opening the database at startup (it is the same open every rmj command does; the tools stay gated by the switch); `shell` stays false because the ledger keeps one display string; the live Tailscale read keeps its own 10 s limit (the status call answers in milliseconds when the daemon is up); the symlink race on the archive file (the directory is mode 0700 and the user's own); whole-ledger paging (about 1.6k rows at 30 days of history).
