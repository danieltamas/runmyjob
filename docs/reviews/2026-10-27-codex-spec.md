# Codex review of the spec, 2026-10-27

Prompt: a full read of every document; findings P0..P3, one per line. 60 findings. What was folded in and what was declined, with reasons, is in LOG.md.

P0 Tenant classification can bypass the deny: docs/ROUTING.md "Tenants" defaults unknown origins to `personal`, permits personal jobs on either company box, omits a concrete `[repo]` schema, and does not explicitly classify gateway under the personal account. In PLAN.md U3, define canonical repository identity and override precedence, explicitly map company repositories, and keep unidentified repositories local until classified.
P0 Verified address is not bound to SSH: docs/ROUTING.md "Reachability" checks resolution but subsequently connects through an alias whose DNS or inherited `ProxyCommand`, `ProxyJump`, forwarding, or multiplexing settings can change the actual connection. In U1/U4/U6, connect to the verified peer IP with the correct host-key alias and explicit transport options, applying the same policy to rsync.
P0 The argv guarantee contradicts execution: SECURITY.md promises literal arguments, but docs/ROUTING.md executes a reconstructed command through `bash -c`, where shell syntax is interpreted despite outer quoting. In U4, preserve an argument array through local and remote execution, provide an explicit shell-command mode when needed, and test literal metacharacters separately from intentional shell syntax.
P0 Exit 125 can execute a command twice: docs/ROUTING.md and PLAN.md U4 treat any remote exit 125 as a container-start failure, although a successfully started command can itself return 125. Return a separate launch-status record and allow local fallback only after proving that the remote command never started.
P0 Concurrent sync can change a running build: docs/ROUTING.md syncs every invocation into the same worktree directory using `--delete`, allowing another agent to replace files underneath an active container. In U4, serialize sync and execution for that directory or give each run an isolated snapshot, including distinct identities for clones with matching directory names.
P0 The Ledger lock can outlive its protection: PLAN.md U4 ports an SSH-side lock while the detached container can survive the SSH client, allowing the lock to disappear while database-resetting work continues. Hold the lock for the actual container lifetime and test client death followed by a second Ledger invocation.
P0 Stale-registration pruning deletes runners RMJ does not own: PLAN.md U6 and the vendored entrypoint delete every `offline, busy=false` registration in a target, including unrelated machines and temporarily disconnected runners. Restrict deletion to recorded RMJ-owned registrations, require an offline grace period, and revalidate identity and state immediately before deletion.
P1 Local execution loses its outcome: docs/ROUTING.md makes `local` a job state alongside `done` and `failed`, so a fallback command that fails cannot be represented consistently or reliably appear in failures and notifications. In U2/U4/U7/U10, store execution location and fallback reason separately from lifecycle state and exit status.
P1 Local fallback can produce misleading verification: PLAN.md U4 assumes the Mac can execute the remote command equivalently, while the existing Ledger environment deliberately runs checks that skip or cannot run on the Mac. Record the changed execution environment, distinguish unavailable prerequisites from test success, and visibly identify reduced verification when fallback occurs.
P1 Remote execution lacks a durable identity handshake: docs/ROUTING.md uses second-resolution container names and does not specify how they map to ledger ULIDs or how a lost launch response is reconciled. In U2/U4, allocate and persist the ULID before dispatch, use it in remote names and records, namespace paths by canonical repository/worktree identity, and make launch reconciliation idempotent.
P1 Capacity checks race and ignore the actual memory budget: PLAN.md U3 skips destinations using an observed running-job count, so concurrent CLI invocations can all claim the same slot, while three 12 GB rx jobs can overlap the existing runner stack and GPU workload. In U3/U4/U6, reserve capacity transactionally and enforce an owner-configured combined resource budget with headroom, addressing the freeze recorded in LOG.md.
P1 Reboot recovery cannot satisfy the promised logs: docs/ROUTING.md writes logs and metadata after completion through a detached waiter, which does not survive a box reboot and can leave neither final records nor cleanup. In U4/U6, persist output during execution, identify the container and boot, reconcile interrupted containers after reboot, and publish completion records atomically only when their associated files are ready.
P1 Cancellation and detachment are undefined: PLAN.md U4 says killing the client leaves no container, while the box contract intentionally lets the command continue until completion, and no cancellation operation is specified. Define Ctrl-C, timeout, app quit, and detached-client behavior separately; add cancellation for owned local and remote jobs and test eventual cleanup without assuming immediate completion.
P1 Exact timing relies entirely on adjustable clocks: PLAN.md U2 and docs/ROUTING.md call Docker wall-clock subtraction exact, but neither clock adjustments nor monotonic elapsed time are specified, and the stored offset has no model field or uncertainty. Record elapsed durations independently where possible, retain timestamp provenance and offset uncertainty, and mark interrupted or contradictory timing as unknown.
P1 GitHub queue timing has no defined job-level source: PLAN.md U5 calculates `started_at - created_at` without specifying whether creation belongs to the workflow run or the individual job, which matters for dependency-blocked jobs. Define timestamps and provenance per job attempt, separate dependency wait from runner wait where observable, and mark estimates explicitly.
P1 GitHub and local logs have no archive implementation: PLAN.md U2 describes pulling rx files, while U5 only reads GitHub metadata and U4 does not define durable local-output capture. Add archive paths for local execution and GitHub job attempts, including failed-job logs, so panel inspection and AGENT-API.md tools work for every advertised source.
P1 Successful logs are not retained on both sides: README.md and PLAN.md promise 30-day logs on the box and Mac, but U2 only copies successful logs on demand. Either archive every completed run locally in U2 or explicitly narrow the promise and display which logs depend on the remote box remaining available.
P1 Failed-log collection has no retry lifecycle: PLAN.md U2 pulls a failure log "as soon as" completion occurs, but completion may happen while the Mac sleeps, the app is closed, or the destination is unreachable. Persist pending collection, retry during reconciliation, distinguish pending from unavailable logs, and avoid caching an incomplete running log as the final copy.
P1 Automatic pruning stops when work stops: docs/ROUTING.md prunes the box only when another run finishes, so an idle box retains files indefinitely, and the inherited `-mtime +30` does not implement an exact 30-day cutoff. In U2/U4, define retention from completion time and implement periodic reachable-box pruning, explicitly documenting whether unattended expiry requires a box timer or waits for the Mac.
P1 Retention can delete evidence for unfinished work: PLAN.md U2 tests deletion of an "older than 30 days" job without identifying the timestamp or protecting running, lost, reconciling, and pending-log rows. Base expiry on confirmed completion, preserve active recovery records, and delete related rows and files through a recoverable cleanup sequence.
P1 Thirty days does not bound disk consumption: PLAN.md U2/U4 sets no limit for a noisy running log, Docker's underlying logs, concurrent downloads, or total archive size. Add streaming and storage bounds, explicit truncation markers, and disk-full behavior that preserves the command's outcome and reports lost output.
P1 Raw logs contradict the secret guarantee: SECURITY.md forbids PATs in logs, while U2 and AGENT-API.md retain raw bytes and redact only on display, allowing an accidentally printed PAT to remain on disk. Redact known credentials before persistence and every external output, handle secrets split across stream chunks, and apply the policy to command metadata, errors, notifications, and pulled logs.
P1 A Database actor is not a cross-process writer: docs/ARCHITECTURE.md calls the actor a single writer even though every app and CLI process opens its own instance, leaving event ordering, terminal-state updates, and migration ownership unspecified. In U2/U4, define transactional state transitions, uniqueness constraints, migration locking, and how the open panel observes CLI writes.
P1 Hooks make fallback jobs invisible: PLAN.md U9 explicitly lets locally routed commands pass without a ledger row, contradicting docs/ROUTING.md and the owner's requirement to see local fallbacks and their reasons. Add a supported execution/completion wrapper for intercepted jobs or narrow the coverage promise and show the tracking gap clearly in Settings and README.md.
P1 GitHub routing is presented as app-controlled without an execution mechanism: PLAN.md U3 accepts workflow/job inputs, but U5 only watches GitHub, whose `runs-on` labels select the runner independently of `rules.toml`. Define rx rules and GitHub label routing separately in U3/U5/U7, showing the workflow selector, eligible runners, destination mapping, and configuration mismatches.
P1 GitHub attempts and outcomes cannot be represented faithfully: docs/ROUTING.md lacks attempt identity, provider status/conclusion, and several nonfailure outcomes, while U6 can mark a GitHub job lost even when GitHub still reports it running. In U2/U5/U6, preserve attempt history and provider truth, and model destination connectivity separately from the execution outcome.
P1 Polling can silently omit jobs from the promised history: docs/ARCHITECTURE.md fetches 50 workflow runs and PLAN.md U5 fetches only seven completed days, without pagination or a discovery contract for repository globs and organizations. Define the watched repository set, paginate ingestion, backfill gaps after downtime, and expose incomplete coverage within the 30-day history.
P1 Rerun does not identify what will actually rerun: PLAN.md U5 uses run-level `--failed` for a selected job and omits an explicit repository, while U4 reruns a checkout that may have changed or disappeared. Bind GitHub requests to repository and job/run identity, retain a parent-attempt link, and show whether an rx rerun uses changed files or cannot recreate the original input.
P1 Tailscale discovery depends on unspecified DNS behavior: docs/ROUTING.md does not define stable peer identity, short-name normalization, literal-IP configuration, MagicDNS-off operation, or split-DNS disagreement. In U1, select the peer from Tailscale status, connect using its verified address, and add fixtures for DNS changes, expired keys, exit-node use, and permitted Tailscale relay transport.
P1 Mac sleep has no lifecycle contract: PLAN.md U1/U4/U6 does not specify whether sleep detaches jobs, suspends local work, invalidates probes, or immediately reconciles on wake. Add wake-triggered connectivity refresh and reconciliation, suppress misleading heartbeat failures caused by sleep, and keep a remote job potentially running until evidence establishes its outcome.
P1 Cached availability has no freshness limit: PLAN.md U3 requires routing from cached state, but docs/ROUTING.md requires verification at every connection and does not define behavior when the app is closed or the cache is stale. Specify persisted cache ownership and maximum age, then revalidate immediately before remote actions without turning an uncertain launch into a duplicate local run.
P1 Runner operations can interrupt active jobs: PLAN.md U6 refuses busy recreation but leaves stop, restart, deploy, image replacement, and resource changes unrestricted. Apply the same current-state checks to every disruptive operation, provide a drain path, and require explicit cancellation when the owner chooses to interrupt a running job.
P1 The default rules shadow local cargo builds: docs/ROUTING.md puts the broad Cargo rule before the `cargo build` local rule, so first-match evaluation can send a Mac build to Linux. In PLAN.md U3, put the specific local rule first, define one-word versus two-word command matching precisely, and test the shipped rule order.
P1 The Ledger rule does not reproduce the working environment: docs/ROUTING.md names `gh-runners_default`, while the predecessor uses `gh-runners_ci` plus specific mounts, environment variables, and developer-service forwards that the rule schema does not represent. In U3/U4, specify the complete working profile and test it against the separate developer database pair before claiming an unchanged port.
P1 Running rows do not show meaningful progress: docs/DESIGN.md "Jobs" provides elapsed time and an expanded log tail but no current GitHub step, completed-step count, sync progress, or last-output age. Add phase/current-step indicators and activity timestamps in U4/U5/U7, using indeterminate progress for arbitrary commands without measurable completion.
P1 Concurrent agent jobs are visually indistinguishable: docs/DESIGN.md "Jobs" omits branch, worktree, short commit, and session identity from the visible row despite several agents building the same repository. In U7, add a compact branch/worktree line and expose session identity and dirty-checkout provenance in the expansion.
P1 Failed and fallback rows hide essential outcome information: docs/DESIGN.md puts log and rerun actions inside the expanded row and gives local jobs a location label without a defined running or failed outcome. In U7, show outcome, duration, fallback reason, and log availability together, with visible Log and Rerun actions for failures.
P1 Queued rows cannot explain the runner problem at a glance: docs/DESIGN.md only specifies wait duration and a reason string, omitting required labels, eligible-runner count, busy/offline counts, and when the evidence was checked. P1 Destination cards omit routing capacity and readiness: docs/DESIGN.md shows load and containers but not destination roles, occupied versus configured rx slots, configured limits, or whether a reachable box can accept the selected job type.
