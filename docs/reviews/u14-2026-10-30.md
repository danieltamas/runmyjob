Checked U14's diff, spec, credential lifecycle, hostile imports, routing/fallback, RunEngine, and box shell syntax; review was read-only.

P0 Sources/RMJCore/Run/AgentBranch.swift:128 - Git filters remain enabled for agent-controlled content - An existing clean driver such as `./scripts/clean` can be selected through returned `.gitattributes`; replacing that script in the returned tree makes `git add` execute agent code on the Mac.
P0 Sources/RMJCore/Run/AgentSession.swift:37 - The prelude moves credentials from tmpfs onto container disk - DockerPlan supplies no tmpfs for `/tmp`, so `$HOME/.claude/.credentials.json` enters Docker's writable layer and survives a Mac or waiter crash while the container remains.
P0 Sources/RMJCore/Run/RunEngine.swift:263 - The staged access token is never added to output redaction, and the box records raw output - An unattended agent printing its credentials file puts the token in `~/rx/.logs/<id>.log`, the Mac archive, terminal output, and any enabled log sink.
P0 Support/box/rx-run.sh:163 - Secret creation follows existing directories and symlinks without checking ownership or mode - On the `/dev/shm` path, another box user who learns the job ID can precreate an accessible directory or symlink; `mkdir -p` accepts it and `cat` writes the access token where that user can read it.
P1 Sources/RMJCore/Run/RunCommand.swift:45 - Context-open failures bypass `--require-box` - An unwritable RMJ_HOME or unavailable database causes `rmj agent run --require-box` to launch Claude on the Mac; RunEngine's ledger-insert failure at line 112 has the same bypass.
P1 Support/box/rx-run.sh:89 - Neither staging nor returned-path validation proves that credentials reside on tmpfs - A disk-backed XDG_RUNTIME_DIR is accepted, and AgentSession accepts arbitrary absolute paths ending in `/rmj-<id>`, including traversal components, so credentials can be staged and mounted from disk.
P1 Support/box/rx-run.sh:84 - Credential cleanup depends on the Mac reaching `unsecret` - If the Mac dies after staging but before launch, the waiter exits without removing the token; pruning only runs on later activity and only removes directories older than a day.
P1 Sources/RMJCore/Run/AgentTask.swift:25 - The deadline sends TERM without a subsequent kill deadline - A harness or child ignoring TERM keeps `timeout` and the container alive indefinitely after the Mac disconnects.
P1 Sources/RMJCore/Run/TreeSync.swift:77 - The aggregate import limit is enforced only after downloading everything - An agent producing many files below 25 MB can exhaust the Mac's disk before AgentBranch checks its 512 MB limit.
P2 Sources/RMJCore/Run/AgentBranch.swift:74 - The result commit uses HEAD at import time instead of HEAD at task start - If the owner commits or switches branches during the run, the result receives the wrong parent and can appear to revert intervening work.
P2 Sources/RMJCore/Run/RunEngine.swift:250 - Result collection happens after the box waiter releases the checkout lock - A queued run can acquire the lock and rsync over the shared directory before `pullTree` finishes, causing the first job to import the second job's files or a mixed tree.
P2 Sources/RMJCore/Run/TreeSync.swift:73 - Pull exclusions apply `.gitignore` to tracked files too - A tracked file matching an ignore pattern is sent to the box but omitted on return; `git add -A` then records its deletion even when the agent left it unchanged.
P2 Sources/RMJCore/Run/AgentRunCommand.swift:53 - Timeout-unit multiplication can overflow - `--timeout 9223372036854775807h` parses as an Int and then traps during multiplication instead of returning usage exit 2.
P2 Sources/RMJCore/Run/RunEngine.swift:252 - Import failure does not affect the returned job outcome - A successful harness followed by rsync, size-limit, or Git import failure still returns exit 0 and a done ledger row despite producing no reviewable branch.
## Outcome

Round 1: all four P0 fixed (isolated scratch repository for tree building, `--tmpfs /tmp` plus a tmpfs check and fresh
directory on the box, token added to redaction, `mkdir` without `-p` with owner and symlink checks). P1: require-box now
holds on ledger and context failures; the returned directory is rejected if it has `..`; tmpfs is verified on the box.
Not changed, with reasons: TERM-only timeout (the box argv is fixed by the acceptance tests; open), aggregate pull size
(the box and its agent are the owner's), staged secret left if the Mac dies before `go` (tmpfs, pruned after a day; the
file leaves the shared mount as soon as the container starts). P2: parent is the HEAD at the start, `--timeout` overflow is
a usage error, import failure returns exit 4; the lock released before the pull is documented, not changed.

Round 2 (`docs/reviews` text above is round 1): 0 P0.
- P1 box log keeps the raw token if the agent prints it: documented as a known limit (the Mac side is redacted; a redactor
  for token shapes in the reconcile path would close it).
- P2 tracked-but-ignored files: the reviewer was right that the sync sends them; the snapshot and pull were corrected to
  follow git's own list and a test (written by Codex) covers it.
- P2 pull filter trusted the agent's .gitignore: fixed by the same change (git's list from the Mac, not a pattern file).
- P2 ledger row says done when the import failed (exit 4 is the caller's signal); P2 unborn-HEAD parent edge: both accepted.
